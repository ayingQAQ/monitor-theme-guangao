## 结论与范围

在下列检查范围内，主题实现符合公开页架构与接口约定；发现并修复了两个实时数据处理问题。此次只修改数据接收逻辑、验证代码及文档，没有新增样式修改。

这是主题客户端检查，不是 Hub 或 agent 的完整协议审计。浏览器消费公开快照，agent 的 Bearer 鉴权、JSON-RPC 上报、数据库累计和节点隐私字段过滤属于 Hub/agent 的实现职责。本次未修改这些服务。

## 数据与运行方式

- 生产构建为静态 SPA。演示接口仅在 Vite 开发插件中启用；对正式 `dist` 的扫描没有发现演示节点名、演示插件或测试错误页字符串。
- 网速使用 `net_rx/net_tx` 的 B/s 数值；累计及本月流量使用 Hub 返回的统计值，`month_used` 缺失时按 `traffic_mode` 兼容处理，没有从历史曲线积分估算流量。
- 在线状态读取 `online`；指标缺失不会变成零速。单个异常 metrics 不会阻止其他节点展示。
- 分组顺序由节点排序决定，以 `null` 表示全部分组，避免与任意组名碰撞；汇总随选择的分组更新。
- 到期和离线时长优先采用服务端字段，并区分字段缺失与 `null`。费用格式、账期和旧 Hub 兼容已有单元校验。
- 公告和节点备注采用 React 文本渲染，无原始 HTML 注入。站点设置读取 Hub；本地存储仅保存访客配色、动效和边框灯偏好。
- 页面隐藏时停止节点连接、轮询及重试，忽略旧请求结果；恢复前台立即读取并重连。该行为通过模拟可见性事件验证。
- `/node/{id}` 支持刷新、前进和后退，README 已列出反代放行路径；固定路径 favicon 和 Apple 图标声明齐全。

## 本次修复

## 实测限制与发布状态

### v0.1.1 安装包修正

此前的打包检查只覆盖文件、大小与 gzip 完整性，没有覆盖 Hub 安装器对压缩包根目录的要求，导致 v0.1.0 的 `theme.json` 被多余的外层主题目录包住。这个包在真实 Hub 的上传接口复现了「主题包里没有 theme.json」错误。

v0.1.1 将 `theme.json`、`dist/`、截图和许可文件直接放在压缩包根目录。Hub 读取清单后自行创建 `<short>` 安装目录。打包流程现在自动运行 `scripts/check-package.mjs`；该校验在旧包上失败，在修正版上通过。修正版已通过真实 Hub 上传安装，验证时保留原站点设置。

独立 Hub 当前没有节点，因此真实非空历史、延迟探测和匿名节点隐私字段过滤尚未实测。相关客户端行为使用明确的测试数据验证；不能据此宣称 agent 上报全链路已经验证。

实测使用独立的测试 Hub。本次只读取远端数据，未修改或重启服务、未部署当前本地包。个人部署记录不包含在公开仓库中。

初次检查时项目使用旧短名，随后统一命名为 `monitor-theme-guangao`。配置路径和清单短名同步采用新名称，压缩包根目录布局以 v0.1.1 的修正为准；公开发布状态见 README 和 GitHub Release。新名称现已通过真实 Hub 的主题包上传安装验证。
