# 滑动与详情性能检查

## 已确认的开销

- 手机尺寸下，六张演示卡片及页内装饰合计创建 67 个动画。屏幕外卡片原先仍运行；两套边框效果同时更新背景，其中一套还使用覆盖整卡的复合遮罩。
- 闪光效果在动画帧中改变 drop-shadow 滤镜，指标光影另叠加 blur 滤镜，增加栅格化开销。
- 实时节点快照使详情组件每次重新渲染历史图表。修改前的回归测试观察到一次实时上报产生 20 条图表 DOM 变更，尽管历史数据没有变化。
- 触屏设备可能保持 hover 状态，原卡片 hover 会产生额外位移和过渡。

## 修改

- 使用共享 IntersectionObserver 暂停视野外装饰，进入视野前 80px 恢复，无滚动事件监听和逐帧 React 状态更新。没有添加 content-visibility、强制 GPU 分层或整卡裁切，避免改变卡片高度与贴纸、光影溢出效果。
- 外层边框改为原生虚线，保留内层跑马灯并限制其背景绘制步数；删除冗余光影 blur，闪光改为透明度呼吸。三种皮肤、颜色、卡片比例和字体保持原设定。
- 历史区域拆为 memo 组件，仅节点 ID、容量、保留天数变化或自身历史操作时更新。实时状态与事实信息继续更新，图表工具提示、缩放、范围切换、峰值区间继续保留。
- 实时快照通过 React transition 更新，使点击等交互优先；不改变 WebSocket 协议、采样或故障重试逻辑。
- 卡片 hover 位移仅用于有精细指针和 hover 能力的设备，触摸点击不触发悬停位移。

## 验证与限制

开发演示、Chromium、390×844、四倍 CPU 降速：记录 2 秒等待及 20 次步进滚动的 devtools.timeline。一次修改前/后对照中，Paint 累计耗时由 1254ms 降至 172ms，UpdateLayoutTree 由 1049ms 降至 682ms。这是开发环境特定模拟结果，不是手机实测 FPS、普遍提升比例或性能保证。

两项回归测试验证屏幕外动画暂停/恢复且高度不变，以及实时事实更新时历史图表不发生 DOM 变更。现有测试继续覆盖三种皮肤、广告过滤兼容性、边框灯、动效开关、路由与历史操作。另在触摸设备、双倍像素比和四倍 CPU 降速模拟中滚动紫绿皮肤并点击详情，检查截图中的完整卡片显示。

用户 Via 截图有大片漏绘，但截图不足以确定具体 WebView/GPU 原因。此次优化针对已测得的绘制开销；实际设备上的漏绘是否消失仍需升级后检查。
